# 长截图 v2.1 —— 滚轮后必须给出结论

## 用户口径（m01805 / m02057）
- 滚轮滚过之后就要读，不许静默卡在第 1 帧。
- 只拼接静态帧里能拼的部分；内容太长或有动态拼不上，就明确提示「拼接失败」，保留已拼部分。
- 不要为了拼接写更聪明的算法（QQ 也做不到），失败要看得见。

## 旧行为为什么卡 1 帧（实测，非猜测）
1. 覆盖层用 `Region` 在选区挖洞，OS 把滚轮投给**光标下**的窗口（`HKCU\Control Panel\Desktop\MouseWheelRouting=2`），
   所以覆盖层自己**收不到** `WM_MOUSEWHEEL`，`OnMouseWheel`/`wheelPending` 基本不触发。
2. 于是只剩 90 ms 定时器采样 + 两道门：`ImagesIdentical`（只抽 5 行）要求整块像素完全一致才 `stableCount=1`；
   一旦选区里有任何动像素（光标、时钟、动画），这道门永远不过 → `AddFrameIfNew` 一次都不执行 → 预览停在 1 帧。
3. 旧 `FindVerticalOverlap` 是对上一帧的**精确**整块匹配，一个动态像素就返回 -1，且失败是静默的。

## v2.1 的做法
| 环节 | 旧 | 新 |
| --- | --- | --- |
| 变化检测 | 24x18 亮度网格（白底细线滚 120px 也判「没变」） | `LongStitcher.RowHashes`：逐行 FNV-1a 指纹，跳过右侧 18px，步长 3 |
| 判定时机 | 整块像素一致才采样 | 内容一动就记候选；候选**静默一 tick** 立刻提交；连续动画每 900 ms 强制给一次结论 |
| 匹配 | 对上一帧精确匹配，失败静默 | 对**整张画布**逐 k 打分，取最优点；容忍 `max(k/40, k/10)` 行动态行；`Anchored` 要求 ≥24 连续相等行；`hintStep` 用上次步长破自相似歧义 |
| 增长 | 只向下 | 向下 + 向上（回滚只定位不截短） |
| 失败 | 静默 | 连续 2 次拼不上 → 预览面板红字「拼接失败：选区内容有动态变化，已保留可拼接部分」；确定时先弹标题「长截图」的提示框，再进编辑器；超过 20000 px → 「拼接失败：内容过长」 |

## 已知边界
- 动态区域占重叠区 >10% 时一律判失败并提示，不做修补（用户明确不要更聪明的算法）。
- 拼接画布上限 20000 px；超限停止采集并提示。
- 连续动画时每 900 ms 给一次结论，因此「滚动 → 预览更新」在动画区可能延迟最多约 0.9 s；静态区通常 1~2 tick（≤200 ms）。
